# LoRA 论文要点

## 1. 核心公式

```
W_new = W_0 + ΔW
      = W_0 + (α/r) × B @ A
```

- `W_0`: 原始冻结权重，shape = (d_out, d_in)
- `A`: 下投影，shape = (r, d_in)，随机高斯初始化
- `B`: 上投影，shape = (d_out, r)，**初始化为 0**
- `r`: 秩，通常 4-64
- `α`: 缩放因子，`scaling = α / r`

**为什么 B=0？** 初始化时 ΔW = B @ A = 0 @ A = 0，因此在无 dropout 等额外差异时，LoRA 分支不会改变原层输出。如果 B 也随机初始化，则一开始就引入非零扰动。

## 2. SVD 视角（为什么有效）

```
ΔW = B @ A    shape: (d_out, d_in), 但秩只有 r

LoRA 的参数化约束: rank(ΔW) ≤ r
经验假设: 任务适配可能集中在较低维的有效更新子空间
不能由此推出: 任意任务上 r = 8 都足够
```

LoRA 论文报告了多个模型/任务上的性能实验，并对 GPT-3 的 LoRA 更新方向做了经验分析。这支持进一步研究“适配更新可能具有低内在维度”，但不是对所有模型、层、任务和 rank 的数学保证。尤其不能把 LoRA 自身的 `BA` 当作独立证据：它按构造已经满足 `rank≤r`。本项目若要验证该假设，应分析未受低秩约束的 full-FT `ΔW_full`，再用下游 rank 消融验证。

## 3. 参数量对比

```
全量微调: 每层 d_out × d_in 个参数
LoRA:     每层 r × (d_out + d_in) 个参数

例: d_in = d_out = 4096, r = 8
  全量: 4096 × 4096 = 16,777,216
  LoRA: 8 × (4096 + 4096) = 65,536
  比例: 65,536 / 16,777,216 ≈ 0.4%
```

## 4. 为什么只适配 q_proj 和 v_proj（Table 4）

论文实验（GPT-3 175B, WikiSQL, MultiNLI）：

| 适配模块 | WikiSQL | MultiNLI | 可训练参数 |
|---------|---------|----------|-----------|
| 只适配 q | 73.2 | 89.6 | 基准 |
| 只适配 k | 72.9 | 89.3 | 同上 |
| 只适配 v | 73.1 | 89.6 | 同上 |
| **q + v** | **73.7** | **90.0** | **2x** |
| q + k + v + o | 73.9 | 90.2 | 4x |
| 全部（含 FFN）| 74.0 | 90.3 | 很多 |

结论边界：在表中给定的 GPT-3 任务和预算下，q+v 以较少参数接近“更多 attention 投影”的结果，因此可作为候选起点；不能把任务分数换算成“95%+ 效果”，也不能推出所有任务上 q+v 性价比最高。

**是否增加模块？** 表内差异很小且依赖具体任务。增加 k/o/FFN 会提高容量和训练成本，但不保证更好；应在相同数据、优化步数和计算预算下做 target-module 消融。

## 5. alpha 参数的含义

```
scaling = alpha / rank
ΔW 实际贡献 = (alpha / r) × B @ A
```

- `alpha` 是一个固定常数（常见值 16 或 32）
- `scaling = alpha / r`，当你增大 rank 时，每个 LoRA 分量的贡献自动缩小
- `alpha/r` 控制 LoRA 分支的缩放，但不能保证换 rank 后无需重新调学习率
- `alpha = 2 × rank` 只是常见起始配置之一，不代表自动与原始权重量级匹配；仍需结合优化稳定性和 dev 指标选择

## 6. 推理无额外开销

训练结束后把 LoRA 权重 merge 回原始权重：

```python
W_merged = W_0 + (alpha / r) * B @ A
```

merge 后 LoRA 适配器可以丢掉，推理时就是普通的矩阵乘，零额外开销。这比 adapter（多一层网络）和 prefix-tuning（多一段 prefix 占 KV cache）都好。

## 7. Rank 怎么选

| 场景 | 候选起始范围 | 必须验证的内容 |
|------|----------|------|
| 窄领域、输出结构稳定 | 4/8/16 | 是否欠拟合、格式遵循、跨 seed 方差 |
| 多领域或复杂输出 | 8/16/32 | 容量收益是否超过训练成本与过拟合风险 |
| 通用微调 | 8/16/32 | 领域收益与通用能力保留 |
| 更大模型 | 4/8/16 | 模型规模本身不能决定所需 rank |

rank 太小可能欠拟合；rank 增大提高参数量和容量，但是否过拟合、是否值得以及离全量微调还有多远，都取决于层宽、适配模块、数据和预算，不能只凭 rank 数字断言。
