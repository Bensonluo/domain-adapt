# ADR-001：采用证据优先的 Phase 0 修复方式

- 日期：2026-08-28
- 状态：Accepted
- 决策范围：Phase 0 内容、方法论、验收和总结

## 背景

Phase 0 的学习材料、代码和外部实验较丰富，但执行状态、证据强度和总结结论没有分开管理。典型问题包括：有脚本但无实验结果、外部案例替代原任务、非受控对比被写成因果结论，以及未完成的验收项被总结为已完成。

## 方案比较

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 只修文档 | 最快消除错误表述 | 不增加实验可信度 |
| B. 证据优先最小闭环 | 修正文档与训练目标，并规定少量关键重跑 | 仍不是论文级完整研究 |
| C. 全量研究级重跑 | 可形成较强公开研究证据 | 成本高，不符合基础阶段投入产出 |

## 决策

选择方案 B：

1. 立即修正错误术语、过度主张、完成状态和直接影响训练目标的 masking 行为。
2. 每周保留纠错记录，不覆盖错误形成过程。
3. 将无法通过文档修复的问题列为明确实验债务。
4. 在退出门槛满足前，阶段状态保持 `REMEDIATION_REQUIRED`。

## 后果

- 现有观测值不会被删除，但允许的解释范围会收缩。
- 部分原来的 `[x]` 会恢复为 `PARTIAL` 或未完成。
- 当前测试集如果参与过迭代，应降级为 dev；最终结论需要新 blind test。
- 外部项目证据必须固定到 commit/data/config/result，不能只链接浮动的 `main`。
